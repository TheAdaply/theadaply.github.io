Example · team memory for coding agents

The second time is fast.

When one engineer’s agent works something out, the next agent on the team should start from the answer, even in a different repo, days later.

The setup

An internal service with no docs in the repo and three rules nobody wrote down. We ran Claude Code against it twice: once to learn, once on new work.

01 · last week

An engineer’s agent fixes the client

In the ledger repo the agent probes the service until fetch_balance works, and finds three undocumented rules. The session goes into team memory.

02 · today

A teammate starts new work

In a different repo, reports, an agent must build a monthly export from the same service. Nothing in this repo mentions the rules.

03 · the difference

Memory or rediscovery

With team memory, the agent reads what was learned and gets the call right first time. Without it, it starts probing from zero.

What team memory held, from last week’s session
  • The service requires header X-Ledger-Version: 2026-07-01.
  • Account ids must be lowercase: ACC-77 returns 404, acc-77 works.
  • Money comes back as amount_minor (string) and exponent.

Method: Claude Code on Opus 5.5, October 2026. A test service with undocumented behaviour, running outside the repos so its source couldn’t be read; every request logged. 1–3 runs per condition. Team memory: summaries of earlier agent sessions that the agent can search (Activeloop’s open-source Hivemind, run locally). Writing the same three rules into the repo’s CLAUDE.md by hand also works (solved in 44 s). Team memory gets the same effect without anyone writing it down.

Why it matters

Most of what agents learn on a team never reaches the code: the header nobody documented, the setting that made training diverge, the robot joint that’s capped below spec. Each rediscovery costs an engineer hours. Reforge carries what one agent learns to the next one, with the team’s permissions, so the second time is fast.
